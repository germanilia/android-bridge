# Optional Home-Server Sync Relay

Android Bridge `0.1.3` adds an optional direct-first relay. The Mac and phone still connect directly on the same LAN when possible. If direct discovery fails, both apps use the configured private relay.

The relay stores device enrollment and pairing metadata only. User payload remains on the endpoints while either device is offline. On reconnect, endpoint journals resume unacknowledged notes, meetings, photos, phone-origin meeting chunks, clipboard updates, notifications, SMS events, and files. Screen frames, gestures, and live call actions are never replayed.

## Deploy

Prerequisites are the existing `homeserver` SSH alias, Docker Compose, Tailscale, Nginx Proxy Manager, and the external Docker network `system_default`.

Run from the repository:

```sh
relay/scripts/deploy-homeserver.sh
```

The script builds a pinned self-contained image for the homeserver architecture, transfers it over SSH, starts the hardened Compose stack, and verifies health. It obtains a trusted certificate for the homeserver's Tailscale MagicDNS name, installs a managed HTTPS/WebSocket route in Nginx Proxy Manager, and prints the Mac endpoint, Android endpoint, and one-time Mac setup code. No container port is published on the host.

After the repository-local Git hooks are enabled, every push targeting remote `main` runs this deployment through `scripts/update-local-apps.sh`. Git has a pre-push hook rather than a post-push hook, so the Mac, optional connected Android phone, and relay update before Git sends `main`. The routine never passes `--clean-volume`; existing enrollment state survives redeployment. Any relay deployment failure stops the push.

## TLS requirement

The apps reject plaintext relay connections.

The deployment uses the homeserver's `*.ts.net` MagicDNS name and a Tailscale-managed Let's Encrypt certificate. The endpoint resolves only through the tailnet and remains unreachable to devices outside it. Do not downgrade the apps to `http://` or `ws://`.

## Enroll the Mac

In Mac **Settings → Remote relay**:

1. Enter the printed Mac `https://<homeserver-magicdns-name>` endpoint.
2. Enter a private workspace ID such as `home`.
3. Enter the one-time setup code printed by the deploy script.
4. Select **Enroll Mac**.
5. Select **Create phone invitation** and copy the invitation.

The setup code is single-use and expires after 15 minutes. The phone invitation expires after 10 minutes.

## Enroll Android

In Android **Settings → Relay**:

1. Enter the printed Android `wss://<homeserver-magicdns-name>` endpoint and save it.
2. Enter the phone invitation generated by the Mac.
3. Select **Enroll device**.
4. Enable relay on both apps.

Credentials are unique per device. Android stores its credential in Keystore-backed encrypted preferences; macOS stores its settings and credential in Keychain.

## Behavior

- Direct LAN is attempted first for five to six seconds.
- Relay starts automatically when direct connection is unavailable.
- A waiting relay connection remains ready while the peer sleeps.
- Endpoint-local journals resume from acknowledged cursors after reconnect or restart.
- Duplicate operations are applied idempotently.
- Concurrent note edits preserve a visible conflict sibling instead of overwriting either version.
- Second Brain Markdown and meeting JPEG/PNG projections coexist with Syncthing through content hashes and echo suppression.
- Mac-local meeting audio never syncs to the phone. Phone-origin meeting chunks may transit the relay to their configured Mac storage.

## Logs and retention

The relay logs to the container console (`docker logs android-bridge-relay`) and to a
durable file in the `/logs` volume (`android_bridge_relay_logs`). File logs roll daily
and are retained for **4 days**, capped at 512MB total, configured in
`relay/src/main/resources/logback.xml`. Set `RELAY_LOG_DIR` to relocate them.

The Docker `json-file` driver has no time-based rotation, so `docker logs` output is
bounded by size instead (`max-size: 32m`, `max-file: 4`).

Every frame the relay cannot deliver is recorded as `event=frame_undelivered` with
`result=peer_absent` or `result=peer_backpressure`. Payload contents are never logged.

## Malformed frames do not drop the link

A frame that fails to decode or that the peer's sync engine rejects is logged and
skipped; the connection stays open. Tearing the link down instead would strand the
frame in the sender's journal, so it would be replayed on every reconnect and the link
would flap indefinitely.

## Reset and revocation

Removing the relay credential in either app disables relay on that device. The relay API supports authenticated peer revocation. Deleting the Docker named volume `android_bridge_relay_config` resets every enrollment and should only be used intentionally.

## Back up relay configuration

Follow `relay/deployments/homeserver/README.md`. The backup contains credential hashes and pair metadata, not user payload.
