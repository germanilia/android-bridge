# Optional Home-Server Sync Relay

Android Bridge `0.2.0` adds an optional direct-first relay. The Mac and phone still connect directly on the same LAN when possible. If direct discovery fails, both apps use the configured private relay.

The relay stores device enrollment and pairing metadata only. User payload remains on the endpoints while either device is offline. On reconnect, endpoint journals resume unacknowledged notes, meetings, photos, phone-origin meeting chunks, clipboard updates, notifications, SMS events, and files. Screen frames, gestures, and live call actions are never replayed.

## Deploy

Prerequisites are the existing `homeserver` SSH alias, Docker Compose, Tailscale, Nginx Proxy Manager, and the external Docker network `system_default`.

Run from the repository:

```sh
relay/scripts/deploy-homeserver.sh
```

The script builds a pinned self-contained image for the homeserver architecture, transfers it over SSH, starts the hardened Compose stack, verifies health, and prints a one-time Mac setup code.

Configure Nginx Proxy Manager:

```text
Domain: relay.homeserver
Scheme: http
Forward hostname: android-bridge-relay
Forward port: 8080
WebSockets: ON
```

Do not publish container ports on the host.

## TLS requirement

The apps reject plaintext relay connections.

`relay.homeserver` has no public DNS, so public Let's Encrypt validation does not work. Configure NPM with a tailnet-internal CA certificate and trust that CA on the Mac and phone, or expose NPM through a trusted Tailscale HTTPS hostname. Do not downgrade the apps to `http://` or `ws://`.

## Enroll the Mac

In Mac **Settings → Remote relay**:

1. Enter `https://relay.homeserver`.
2. Enter a private workspace ID such as `home`.
3. Enter the one-time setup code printed by the deploy script.
4. Select **Enroll Mac**.
5. Select **Create phone invitation** and copy the invitation.

The setup code is single-use and expires after 15 minutes. The phone invitation expires after 10 minutes.

## Enroll Android

In Android **Settings → Relay**:

1. Enter `wss://relay.homeserver` and save it.
2. Enter the phone invitation generated by the Mac.
3. Select **Enroll device**.
4. Enable relay on both apps.

Credentials are unique per device. Android stores its credential in Keystore-backed encrypted preferences; macOS stores its settings and credential in Keychain.

## Behavior

- Direct LAN is attempted first for five to six seconds.
- Relay starts automatically when direct connection is unavailable.
- A waiting relay connection remains ready while the peer sleeps.
- Endpoint-local journals resume from acknowledged cursors after reconnect or restart.
- Duplicate operations are applied idempotently.
- Concurrent note edits preserve a visible conflict sibling instead of overwriting either version.
- Second Brain Markdown and meeting JPEG/PNG projections coexist with Syncthing through content hashes and echo suppression.
- Mac-local meeting audio never syncs to the phone. Phone-origin meeting chunks may transit the relay to their configured Mac storage.

## Reset and revocation

Removing the relay credential in either app disables relay on that device. The relay API supports authenticated peer revocation. Deleting the Docker named volume `android_bridge_relay_config` resets every enrollment and should only be used intentionally.

## Back up relay configuration

Follow `relay/deployments/homeserver/README.md`. The backup contains credential hashes and pair metadata, not user payload.
